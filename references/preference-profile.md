# 用户偏好档案（PREFERENCES.md）格式规范

图库根目录的 `PREFERENCES.md` 记录**跨条目的个人审美与习惯**，是实现"图库越长越像你"的载体：条目记录的是原文献的客观画法，本档案记录的是你在复用中反复做出的选择。两套东西各管各的，不许混写。

## 两层结构：整体偏好 ↔ 部分偏好

偏好会长在两个地方，判断"该写哪边"的标准是**适用范围**，不是写在哪里：

| | 整体偏好 | 部分偏好 |
|---|---|---|
| 位置 | `library/PREFERENCES.md` | 各条目 `figure.md` 的「复用要点」「演化记录」 |
| 管什么 | 跨图型的稳定习惯：配色体系、导出规格、英文/字号约定、统计标注方式…… | 只服务这一张图或这一族图的结论：某图的列名映射、某图型的阈值习惯、某变体的坑 |
| 谁读 | 每次复用都读（`retrieve.py` 输出里带稳定偏好） | 命中该条目时才读 |

两者会互相搬家，**定期整理**（见下节）就是搬家的动作：一条规则在多个条目里反复出现 → 晋升为整体偏好；一条整体偏好只服务某一图型 → 下沉回该条目。搬错的代价很直接：留在条目里的通用规则复用别的图时享受不到，写进整体的局部规则会污染所有图。

## 定位与边界

- **读**：模式 B 检索与实例化时必读（`retrieve.py` 已把稳定偏好带进输出）。用户**当前指令** > 稳定偏好 > 条目缺省——用户没说的地方才用稳定偏好填充
- **写**：只记录**可观察到的偏好信号**，禁止脑补。三类合法信号：①你在适配中明确给出的选择（"阈值用 1.5""别用红色"）；②交付后的反馈（"很好用"/"图例放上面"）；③你主动声明的习惯（"以后导出都要 PDF"）
- **与 figure.md 的分工**：某张图特有的适配结论写进该条目的「复用要点」；跨条目通用的习惯（阈值、配色、字体、尺寸、导出规格、常画图型）才进本档案。写档案时若发现某条目复用要点需要同步更新，一并做掉

## 文件结构

```markdown
# 用户偏好档案

（由 agent 在复用交付后自动追加；两类条目：稳定偏好 ≥2 次一致才晋升，单次观察仅备查）

## 稳定偏好
- 显著性阈值：padj<0.05 且 |log2FC|>1.5 〔2026-08-29 火山图任务，2026-09-12 差异热图任务，2 次〕
- 导出规格：300dpi PNG + PDF，宽 ≤6 英寸 〔2 次〕

## 单次观察
- 2026-08-29 〔U1 火山图〕要求数值标签只标 top8，未说是否通用——待复现确认

## 整理记录
- 2026-09-28 整理：晋升 2、合并 3、降级 4、清退 2、下沉 1
```

## 规则

1. **晋升**：两条并列通道——① 同一条偏好在「单次观察」累计 ≥2 次且互不矛盾；② **用户显式声明为通用规则**（"以后都要…""这是通用要求"）。两条都成立就移入「稳定偏好」，标注次数与日期；走第 ② 条时在标注里写明"用户显式声明为通用规则"，脚本据此不再要求重复次数
2. **冲突**：新观察与稳定偏好矛盾 → 以最近为准，把旧偏好移回单次观察并注明被推翻原因
3. **格式**：每行 `偏好内容 〔日期 场景，次数〕`；场景写简短任务描述即可。**每行必须带日期与次数**——整理流程要靠它们判晋升、降级与过期，缺标注的行会被 `review_preferences.py` 直接报出来（用户显式声明的行也要写日期，次数写 1 即可）
4. **容量**：稳定偏好保持 ≤15 行（≥13 行就该开始合并或下沉），单次观察 ≤20 条（≥18 条开始清理）；超限说明该整理了
5. **范围标注**：只适用于某一类图的规则，写进档案时必须标出适用范围（`〔适用范围：热图〕`）；不标范围的默认视为全图型通用——这是最容易出错的地方
6. 本文件是**个人数据**：默认被 .gitignore 排除出公开仓库；私有同步仓库随库走

## 整理流程（定期）

偏好是边用边长出来的，不整理就会：重复行堆积、被推翻的旧规则还留在稳定偏好里、局部规则冒充通用规则、条目里反复出现的规则始终没晋升。**触发条件与节律**（SKILL.md「偏好整理」节）：每次模式 A/B 交付收尾跑一次

```bash
python3 <技能目录>/scripts/review_preferences.py --check    # 退出码 1 = 该整理了
```

到期条件（脚本自动判定）：距上次整理 >30 天、稳定偏好 ≥13 行、单次观察 ≥18 条、自上次整理新增 ≥8 条演化记录，或出现容量/格式/升降级问题。跨条目复现只是"考虑晋升"的提示，不参与到期判定。

### 五步

0. **通读**：脚本只抓字面近似与硬指纹 token（长度 ≥5 的代码 token）。同一件事的两种写法（"热图 cell 要正方形、不留空隙" / "热图格子必须正方形且无缝隙"）要靠通读发现——脚本故意不做模糊匹配，因为领域词重合度区分不了"生信图默认用英文"和"生信图默认只导 PDF"这类共享主语前缀的句子，误报会诱导你合并两条不同的规则
1. **晋升**：用户显式声明为通用规则，或单次观察累计 ≥2 次一致 → 移入稳定偏好，次数与日期累加
2. **合并**：说同一件事的多行合并为一条，保留所有日期（证据不能丢）
3. **降级/推翻**：稳定偏好里只出现 1 次、或已被新反馈推翻的 → 降回单次观察，注明原因
4. **下沉/清退**：只服务单一图型/项目的偏好 → 下沉到该条目「复用要点」；>60 天未复现的单次观察 → 清退

### 候选从哪来

当场写回之外，定期从会话历史里挖用户纠偏（"再改/还是不对/不要/改成"）：

```bash
python3 <技能目录>/scripts/mine_feedback.py --since <日期> --min-count 2
```

产出 `<图库>/FEEDBACK-CANDIDATES.md`（聚类排频的原话 + 日期），**只产出候选**。逐条判断归属：跨图型通用 → 稳定偏好；只服务某项目/图型 → 下沉到条目并标适用范围；一次性要求 → 丢弃。

### 报告怎么用

- `review_preferences.py`（无参数）出人读报告：必做项、跨条目复现、条目内堆积、过期单次观察、疑似冲突
- `--json` 给 agent 逐项执行；`--top N` 控制每节条数
- 脚本**只读不写**：语义合并必须由 agent 判断并落笔，避免机械改坏个人数据
- 整理完在 `## 整理记录` 追加一行：`- YYYY-MM-DD 整理：晋升 N、合并 N、降级 N、清退 N、下沉 N`；脚本靠它判断下次到期时间
- 动过任何 `figure.md` 后跑 `scripts/build_index.py` 重建索引
- 定量侧（条目数、命中率、未命中需求）交给 `scripts/summary.py`；偏好整理只关心偏好本身，两者在交付收尾时一起 `--check`

### 条目侧的整理

「部分偏好」同样会堆积：一个条目被反复改造后，「演化记录」会攒下一串已被取代的中间结论。整理时一并处理：

- 仍然生效的缺省 → 收敛进「复用要点」，演化记录只留"改了什么、为什么"
- 单条目演化记录 ≥5 条（脚本会报"条目内堆积"）→ 说明该折叠一次
- 删掉条目时要清掉其他条目 `related` 里指向它的引用（`build_index.py` 会告警）

### 与 harness 原生记忆的同步（防漂移）

同一份偏好被存到两个地方（例如 omp 的 `managed-skills/*`、项目记忆里的绘图约定副本），早晚会漂移：改了 `PREFERENCES.md` 却忘了那份副本，下一个会话就会拿旧规则画图。整理时：

1. `python3 <技能目录>/scripts/review_preferences.py --digest` 输出一份紧凑摘要（稳定偏好 + 可选单次观察 + 一行检索提醒）
2. 用它刷新 harness 记忆层/托管技能里的那份副本，或直接删掉副本、改成指回 `PREFERENCES.md` 的指针（更推荐后者——单一事实源）
3. 摘要里带的那行"画图前先跑 retrieve.py"顺带把触发钩子也补上了（见 `references/trigger-hook.md`）

## 由 init_library.py 生成骨架

新图库初始化时自动创建带上述结构注释的空档案；老图库缺这个文件时按本规范补建。已有档案缺 `## 整理记录` 节时，整理时补上即可（脚本不写文件）。
