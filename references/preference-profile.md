# 用户偏好档案（PREFERENCES.md）格式规范

图库根目录的 `PREFERENCES.md` 记录**跨条目的个人审美与习惯**，是实现"图库越长越像你"的载体：条目记录的是原文献的客观画法，本档案记录的是你在复用中反复做出的选择。两套东西各管各的，不许混写。

## 定位与边界

- **读**：模式 B 检索与实例化时必读。用户**当前指令** > 稳定偏好 > 条目缺省——用户没说的地方才用稳定偏好填充
- **写**：只记录**可观察到的偏好信号**，禁止脑补。三类合法信号：①你在适配中明确给出的选择（"阈值用 1.5""别用红色"）；②交付后的反馈（"很好用"/"图例放上面"）；③你主动声明的习惯（"以后导出都要 PDF"）
- **与 figure.md 的分工**：某张图特有的适配结论写进该条目的「复用要点」；跨条目通用的习惯（阈值、配色、字体、尺寸、导出规格、常画图型）才进本档案。写档案时若发现某条目复用要点需要同步更新，一并做掉

## 文件结构

```markdown
# 用户偏好档案

（由 agent 在复用交付后自动追加；两类条目：稳定偏好 ≥2 次一致才晋升，单次观察仅备查）

## 稳定偏好
- 显著性阈值：padj<0.05 且 |log2FC|>1.5 〔2026-08-29 火山图任务，2026-09-12 差异热图任务，2 次〕
- 导出规格：300dpi PNG + PDF，宽 ≤6 英寸 〔2 次〕

## 单次观察
- 2026-08-29 〔U1 火山图〕要求数值标签只标 top8，未说是否通用——待复现确认
```

规则：

1. **晋升**：同一条偏好在「单次观察」累计 ≥2 次且互不矛盾 → 移入「稳定偏好」并标注次数与日期
2. **冲突**：新观察与稳定偏好矛盾 → 以最近为准，把旧偏好移回单次观察并注明被推翻原因
3. **格式**：每行 `偏好内容 〔日期 场景，次数〕`；场景写简短任务描述即可
4. **容量**：稳定偏好保持 ≤15 行，超过说明该拆分或合并；单次观察超过 ~20 行时清理已晋升/已过期项
5. 本文件是**个人数据**：默认被 .gitignore 排除出公开仓库；私有同步仓库随库走

## 由 init_library.py 生成骨架

新图库初始化时自动创建带上述结构注释的空档案；老图库缺这个文件时按本规范补建。
