# 交付清单：图件怎么算"能交出去"

这份清单来自对真实使用记录的统计，不是凭空列的规范：在 100 个跑过绘图命令的会话里，**只有 33 个真正看过渲染出来的图**；用户反馈里反复出现的缺陷词依次是文字重叠/遮挡、标题出界、字号与画布比例失调、留白过多、面板大小不一致、配色区分不开、命名混乱。这些**看一眼就能发现**，所以交付前的目视自检是本技能最硬的一条要求。

## 0. 硬要求：交付前必须亲眼看图

1. **渲染完成后，用 harness 的图像读取能力打开最终交付的那几张图**（不是中间产物、不是缩略图）。逐张过下面第 1~4 节。
2. 发现问题 → 改 → **再看一遍**，直到清单全过。改完不看就交付，等于没做。
3. 交付说明里写**看到了什么**："图 X 的 y 轴标签原本与分面标题重叠，已改为竖排并复看确认" —— 而不是"已检查"。没有这句，等于没看图。
4. harness 没有图像读取能力时：退化为检查文件（尺寸/像素/页数/体积，用 `figure_manifest.py` 或 `pdfinfo`/`sips`），并在交付说明里**明确写"未能目视，已做文件级检查"**，不要含糊过去。

## 1. 文字与排版（最高频投诉）

- [ ] 没有任何文字互相重叠或被遮挡：轴标签、分面标题、图例、数据标签、注释文字两两检查
- [ ] 标题/副标题没有超出画布；宁可居中于画布，也不要贴着图边界（用户原话："title 出界了，能不能调整到画布的中央而不是图的中央"）
- [ ] 分类标签拥挤时旋转（竖排）或换行处理；用户明确偏好过"x 轴 label 竖着"
- [ ] 字号与画布成比例：画布大而字小是最常见毛病；分面多时先缩画布或减面板，不要靠放大画布塞内容
- [ ] 分面标题方向按空间选（左侧大类标签用横排外置，右侧竖排容易被裁切）

## 2. 留白与紧凑（第二高频）

- [ ] 上下/左右没有大片空白；画布按内容自适应，但设尺寸上限
- [ ] 多面板图：每个 panel 的**实际绘图区**大小尽量一致（图例大小差异不算），并在代码里显式指定 panel/画布尺寸
- [ ] 热图 cell 是真实正方形、无缝隙；柱状图柱宽统一（当前项目默认 0.55）且偏瘦
- [ ] 拼合大图允许为保证清晰度放大体积（≈ 各子图之和），不要为压体积牺牲文字可读性

## 3. 配色与图例

- [ ] 同类群之间的配色**区分度足够**（用户抱怨过"这样用配色完全区分不开不同的细胞亚型"）——先确认色板能区分目标分组，再谈好看
- [ ] 配色语义与数据方向一致（0 中心发散色、扩增/收缩方向、test/reference 语义）
- [ ] 图例/色键不标注细胞数或任何计数；总量放图题/副标题
- [ ] 图例位置按图调整、不固定；多面板尽量共享图例以便对比；图例不与图形重叠

## 4. 内容正确性（图上画错比画丑严重）

- [ ] 阈值、分母、方向语义与当前任务一致（padj/pval、FC 阈值、test/reference、检出率口径）
- [ ] 分类水平顺序按生物学顺序或自然数值顺序，**不是字母序**；分面之间顺序一致（用户问过"为什么 9-20 的没有按 1-8 一样"）
- [ ] 图上出现的文字都是发表级：不出现脚本路径、算法口径解释、"colours as in (A)"、内部别名、推导式
- [ ] 缺失/空分面已处理（空面板删除或从 levels 去掉），图与清单里的 n/levels 对得上

## 5. 导出规格与命名

- [ ] 默认 PDF 矢量；需要高清预览/上交的项目额外出 JPG（600dpi、quality 100）或 PNG，两者逐面板一一对应（同名不同扩展名）
- [ ] 尺寸显式指定（英寸），不靠默认值；体积在预期范围（项目若有约定按约定）
- [ ] 命名能望文生义：至少包含**层级**（L2/L3/L4）+ **图型** + **分组/方法**；同一批图编号成序（用户明确要求过按编号组织图序）
- [ ] 图件集中放 `figure/<步骤>.<主题>/`，过程数据放 `data_intermediate/`，表格放 `table/`（项目有既定布局时以项目为准，并写进 `PREFERENCES.md` 的适用范围）

## 6. 登记与说明（图件不是"生成完就完"）

- [ ] 图件目录的清单已更新：`python3 <技能目录>/scripts/figure_manifest.py <图件目录> --write`，并填好语义列 `figure_set` / `entry_reused`（复用了哪条配方）
- [ ] `--check` 无漂移（被取代的旧图、失败运行残留已经清掉，而不是躺在目录里冒充最终版）
- [ ] 图族（一整套图）有 README 或 manifest 说明：目的、数据入口、与相邻步骤的区别、口径与阈值；已有项目的 `figure/<step>/README.md` 就是这个角色，续写而不是另起一套

## 7. 复用回执（让"参考了什么"可追溯）

- [ ] 绘图脚本头部写一行：`# Biofigure <条目 id> — <借用的要点>`（项目里已有这种做法，续用即可）
- [ ] 交付说明写明：复用了哪条、按当前数据改了什么、哪些是临摹哪些是适配决策
- [ ] 用户对画法本身的反馈 → 回到条目落实（模板缺省 + 复用要点 + 演化记录），不只是改这一次的代码
