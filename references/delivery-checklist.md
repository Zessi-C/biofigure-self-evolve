# 交付清单：图件怎么算"能交出去"

图件常见缺陷往往高度集中于若干表象：文字重叠遮挡、标题溢出边界、字号与画布比例失调、留白过多、面板尺寸不一、配色区分度不足以及命名混乱。此类问题直观可辨，因而交付前的目视自检是本技能最关键的硬性要求。

**范围说明**：本清单仅界定图件的视觉呈现与交付规范（涵盖图式呈现、命名规则与导出格式）。统计分析口径、数据处理管道以及表格/Excel 交付均超出本技能范围；若遇此类需求，直接交回用户或转由专门工具处理。

## 0. 硬要求：交付前必须亲眼看图

1. **渲染完成后，须调用 harness 的图像读取能力检视拟交付的最终图件**（严禁以中间产物或缩略图充数），并对照下文第 1~4 节逐张核验。
2. 若发现问题，依循「发现问题 → 修改代码 → **复看**确认」闭环，直至通过本清单全部检查项。修改后未经复看即交付，视同未执行自检。
3. 交付说明中必须如实记录**目视所见具体细节**，例如："图 X 的 y 轴标签原本与分面标题重叠，已改为竖排并复看确认"，切勿仅空泛填写"已检查"。凡缺失具体修正与复看记录者，视同未进行目视核验。
4. 若当前环境缺少 harness 图像读取能力，降级执行文件级属性核查（借助 `figure_manifest.py` 或 `pdfinfo`/`sips` 校验尺寸、分辨率、页数及文件体积），且必须在交付说明中**明确写"未能目视，已做文件级检查"**，切勿含混带过。

## 1. 文字与排版（最常见的问题）

- [ ] 杜绝任何文本相互重叠或遮挡：坐标轴标签、分面标题、图例、数据标签及注释文本均须成对交叉检查
- [ ] 标题与副标题均未超出画布边界；宁可基于画布整体居中，也不要紧贴图形边缘（遵循用户明确反馈："title 出界了，能不能调整到画布的中央而不是图的中央"）
- [ ] 分类标签排布拥挤时作旋转（竖排）或换行处理；优先遵循用户明确偏好："x 轴 label 竖着"
- [ ] 字号与画布尺寸比例协调：避免画布过大而字号偏小的常见缺陷；分面较多时优先紧缩画布或删减面板，不要靠放大画布强行塞入内容
- [ ] 分面标题排布方向依留白空间决定（左侧大类标签宜采用横排外置，右侧竖排极易被裁切）

## 2. 留白与紧凑（同样常见）

- [ ] 上下与左右边缘杜绝大面积冗余空白；画布尺寸按内容自适应，但必须设定上限
- [ ] 跨图一致性严格以 `PREFERENCES.md` 中的项目偏好为准（统一色板、字号与尺寸规格），而不是靠脚本跨路径引用共享文件
- [ ] 多面板图：各 panel 的**实际绘图区**尺寸尽量保持一致（图例所占空间差异不计在内），且须在代码中显式指定 panel 或画布尺寸
- [ ] 热图 cell 保持真实正方形且紧密无缝隙；柱状图柱宽统一且偏瘦（若项目或偏好已有约定则从其约定，无约定则统一设定固定值）
- [ ] 拼合大图允许为确保清晰度而适度放大体积（≈ 各子图之和），不要为压缩体积而牺牲文字可读性

## 3. 配色与图例

- [ ] 同类群之间的配色**区分度足够**（针对用户既往反馈"这样用配色完全区分不开不同的细胞亚型"）：须先确认色板能充分区分目标分组，再兼顾美观
- [ ] 配色语义与数据变化方向严格一致（如 0 中心发散色、扩增/收缩指示方向、test/reference 对应语义）
- [ ] 图例与色键中不标注细胞数或任何计数；样本总量统一置于图题或副标题
- [ ] 图例位置依构图动态调整而不设死板固定；多面板图尽量共享图例以利对比；图例严禁与图形重叠

## 4. 内容正确性（图上画错比画丑严重）

- [ ] 阈值划分、基准分母及方向语义与当前任务严格一致（涵盖 padj/pval、FC 阈值、test/reference 与检出率口径）
- [ ] 分类变量水平依据生物学顺序或自然数值顺序排列，**严禁采用字母序**；各分面间顺序必须保持全局一致（对照用户历史疑问："为什么 9-20 的没有按 1-8 一样"）
- [ ] 图件呈现的文字均达发表级标准：绝不出现脚本路径、算法口径解释、"colours as in (A)"、内部别名或推导公式
- [ ] 缺失或空分面已妥善处理（彻底删除空面板，或从 levels 中排除），图件呈现与清单记录的 n 及 levels 严格对应

## 5. 导出规格与命名

- [ ] 默认导出 PDF 矢量格式；针对需高清预览或归档上交的项目，额外导出 JPG（600dpi、quality 100）或 PNG 格式，两者按面板逐一对应（同名且仅扩展名不同）
- [ ] 图像物理尺寸须在代码中显式指定（单位：英寸），切勿依赖默认值；文件体积控制在预期合理区间（项目若有约定按约定）
- [ ] 文件命名须望文生义：至少依序包含**层级**（L2/L3/L4）+ **图型** + **分组/方法**；同批图件依编号成序（落实用户关于按编号组织图序的明确要求）
- [ ] 图件集中归档至 `figure/<步骤>.<主题>/`，过程数据存放于 `data_intermediate/`，表格存放于 `table/`（项目有既定目录布局时以项目为准，并记入 `PREFERENCES.md` 的适用范围）

## 6. 说明与登记

- [ ] 完整图族须配有 README 说明文档：阐述绘图目的、数据入口、与相邻步骤的区别、口径与阈值（已有项目的 `figure/<step>/README.md` 即承担该功能，应在其基础上续写而非另起一套）
- [ ] 若项目使用图件清单（可选）：执行 `figure_manifest.py <图件目录> --write` 完成更新，规范填写语义列 `figure_set` 与 `entry_reused`；运行 `--check` 确保无漂移（被替代的旧图及运行失败残留已彻底清除，严禁滞留于目录中充当最终版）

## 7. 图-表同源与增量重导（可选，仅当项目本来就图-表配对、或图件多到需要清点旧版）

- [ ] 每张拟交付图件均已登记 `source_table`（作为 `figure_manifest.csv` 的列），并经由 `pair_check.py` 核验通过：表格真实存在、非空且无孤立表格
- [ ] 图中所呈数值与表格及清单严格一致（脚本仅能核验"有登记、存在、非空"；具体数值层面须在交付说明中阐明口径并完成抽样核对）
- [ ] 批量重新导出前预先执行 `figure_manifest.py --diff 旧清单.csv --only unchanged`：hash 未变的图件直接跳过，避免重复执行耗时数十分钟的渲染

## 8. 独立验收（要交出去 / 进正文的图）

自主审查难免存在盲区，必须将独立验收与出图环节严格分离：

```bash
python3 <技能目录>/scripts/qa_prompt.py <图件目录> --task "<这批图干什么用>" --out /tmp/qa.md
python3 <技能目录>/scripts/qa_prompt.py <图件目录> --self --task "<这批图干什么用>"   # 没有子代理时
```

- **harness 支持子代理**：将 `/tmp/qa.md` 作为 `task`/`subagent` 的 prompt 传入，验收方仅基于成图独立审查且严禁修改代码，产出**缺陷报告**（逐图列明：结论 + 问题位置/严重度/修改建议）
- **不支持子代理**：使用 `--self` 参数生成自检提示，依循「只看不改 → 记录缺陷 → 修改 → 复看」流程完整执行，并将验收结果记入交付说明

上述两种方式在验收环节均不修改代码、不重新绘图；后续修改统一由出图方依据报告实施，修改完成后再次复看确认。

## 9. 复用回执（让"参考了什么"可追溯）

- [ ] 绘图脚本头部规范添加单行声明：`# Biofigure <条目 id> — <借用的要点>`（项目既有代码已有此规范，沿用即可）
- [ ] 交付说明中须明确记录：具体复用了哪一条目、依据当前数据调整了什么，并厘清哪些要素临摹自参考实现、哪些属于适配决策
- [ ] 用户针对绘图方式本身的反馈，须回流至对应条目中落实（同步维护模板缺省 + 复用要点 + 演化记录），切忌仅修改当次单次代码
- [ ] 图件交付后须执行一次 `retrieve.py --record-used <条目 id> --task "<任务>"`：确保台账具备复用回执，以便 `summary.py` 统计条目采用率，并及时暴露"命中却从未采用"的配方
