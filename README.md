# biofigure-self-evolve

一个自进化的生信画图技能：读文献时看到好图，agent 把画法解剖成记录存进本地图库；等你要给自己的数据画图，它先查图库、照着学过的画法来，而不是每次从零设计。用得越久，图库越大，也越符合你的习惯。

## 这是干什么的

读文献时看到一张好图，想给自己的数据画一张同款，通常得翻回原文猜参数、从头写代码、反复调样式。现成的模板集（比如 [FigureYa](https://github.com/ying-ge/FigureYa)）能帮上忙，但它们靠社区手工维护，收录什么、画成什么样，都不会因为你读了什么而改变。

这个技能把这件事交给 agent。它包含两部分：一个放在技能目录里的本地图库，和一份告诉 agent 怎么维护、怎么使用图库的说明（SKILL.md）。日常用起来是这样的：

- **学习**：你发给 agent 的文献、PDF、公众号文章、截图，都可以被解剖成一条画法记录，这张图由哪些图层组成、需要什么格式的输入、配色和排版怎么处理，连同能直接运行的 R 和 Python 模板，一起存进图库；
- **复用**：等你真的要画图，agent 先去图库里找功能相似的条目，参考它的画法适配你的数据；
- **回流**：你对结果满意的话，这次的画法会被回收进图库；你提的修改意见也会直接改进对应条目的模板。

图库随使用不断生长，这就是名字里的「自进化」。

## 怎么触发

不用记命令，自然说就行：

- 「学一下这个图」「把这张图入库」：发材料时明确要求学习；
- 直接丢来一篇文献或一张截图，agent 觉得里面有值得学的图，会先问一句要不要入库；
- 「照这张图画」「帮我画个火山图」「生存分析画条曲线」：agent 先查图库，有相似的来临摹，没有就正常设计，你满意后它会问要不要把这次的画法存下来；
- 「看看图库都会画什么」：列出已学的条目。

交互环境下，学习前和复用多候选时 agent 会跟你确认；后台任务、管道这类非交互环境则不打扰，直接选最优方案执行，并在结果里说明用了哪条记录、做了什么假设。

## 自进化是怎么实现的

1. **图库变宽**：每学一张图，图库多一条记录，这是最主要的增长方式；
2. **单条记录收敛**：复用之后你对画法本身提的意见（图例挪到底部、标签太挤、阈值习惯）会直接改进这条记录的模板缺省值和配方，改了什么记在条目的「演化记录」里；
3. **跨图偏好沉淀**：在好几张图上反复出现的习惯（比如固定喜欢某类配色、某种图例位置）会写进 `library/PREFERENCES.md`。同一习惯观察到两次才升级为稳定偏好，之后你没明说的细节就默认按它来。

回路有边界：agent 只记录观察得到的信号（你的明确选择、对成图的反馈、主动声明的习惯），不脑补。每条记录里「原图长什么样」是客观事实，不会改；演化的只是配方和模板，而且都有演化记录可追溯。

## 学习一张图时会发生什么

**先判断学什么、按什么粒度学。** 生信文献图的新意常常不在单张图，而在组合与成对叙事上。判断标准是一句话：删掉其中一张图，另一张的信息是否受损？受损就按成组学习，比如「总览 UMAP 的群编号是下一排详情图的行索引」，两者拆开谁都不完整，记录时写清各自的叙事分工；单独都成立但并排更强（比如 UMAP 纵列配 dotplot 和热图）就按组合版式学，重点记录面板之间怎么联动：行序、配色、编号共享；完全独立的各学各的，功能相近的条目用 `related` 字段互指。

**再追溯原始代码。图像只是间接证据，代码才是事实源。** 材料里有代码线索时按四级路径追：正文贴了代码，直接用作一手配方；提到 GitHub 仓库，用 API 列文件树把绘图脚本拉下来；只给了论文，先解 DOI，去 PMC 全文的 code availability 找仓库；都找不到才回到看图反推，并在记录里如实标注「代码未溯源」。这一步经常纠错：有一次从 PMC 找到原论文的绘图脚本，发现 Sankey 其实是 `ggsankey` 而不是肉眼看像的 `ggalluvial`，log2 轴加原始计数标注的实现方式也和猜测完全不同。

**然后写记录、写模板、跑模板。** 每条记录要求 R 和 Python 双模板、内嵌逼真假数据、无参数运行即出图，实际跑通才允许标记 `verified: both`，没跑的如实标 `unverified`。最后过一遍 11 项完工清单（回答什么问题、数据形状、图层可复现、配色具体、排版规格、面板联动、边界与坑、related 登记、模板可运行、原图可溯、代码溯源），缺任何一项不算学完。

## 临摹，不是照抄

复用时提取的是技术骨架：图层组织、映射方式、配色逻辑、排版策略、联动设计。轴、阈值、色值、分组数一律按你当前的数据和目的重新决定；条目只有局部相似时，就只借那一部分。学习时配方也写到技术层面而非参数层面：记「qualitative 色板 + 密度中心标编号」，不记「8 个群必须用这 8 个色号」。

## 安装

```bash
git clone https://github.com/Zessi-C/biofigure-self-evolve.git ~/.agents/skills/biofigure-self-evolve
```

适用于任何遵循 agents/skills 约定的 agent（目录里有 `SKILL.md` 加 name/description frontmatter 就算技能）。依赖很轻：

- 脚本用 Python 3 标准库就能跑（装了 PyYAML 会优先用它，没装走内置的受限解析器，两边都测过）；
- 模板验证需要本机有 R（ggplot2 系）和/或 Python（matplotlib 系），缺哪边，哪边的模板如实标 `unverified`；
- 图库和偏好档案都是纯文本文件，不依赖任何厂商 API、MCP 或联网服务；
- 其他 harness 也一样：只要能读文件、抓网页、跑脚本，就能驱动这个技能；有自有插件格式的，加一层薄适配把 SKILL.md 接进去即可，技能本体不用改。

## 图库里有什么

```text
library/
├── INDEX.json / INDEX.md     # 索引，由脚本从所有 figure.md 全量重建，不要手改
├── PREFERENCES.md            # 跨图偏好档案（个人数据，不进公开仓库）
└── figures/NNN-slug/
    ├── figure.md             # 核心记录：元数据 + 视觉解剖 + 配方 + 复用要点（+ 演化记录）
    ├── reference.png         # 原图参考（仅个人学习用）
    ├── template.R / template.py   # 自包含双模板，无参数运行即出图
    └── template_output_*     # 模板运行产物，作为"已知良好输出"
```

`figure.md` 是唯一事实源，索引只是它的投影。frontmatter 用的是刻意收窄的 YAML 子集（标量、单行列表、一层嵌套），保证没有 YAML 库的环境也能可靠解析。几个关键字段：

- `chart_types` 从近 40 种生信图类型的受控词表里选词（词表见 [references/chart-taxonomy.md](references/chart-taxonomy.md)），学习与检索两端用同一套语言；
- `data_shape` 一行写清这张图需要什么格式的输入，读者扫一眼就能判断自己的表能不能套；
- `use_when` / `not_when` 是复用时语义匹配的主要依据；
- `related` 把同功能变体互指成组（比如「纯 KM 曲线」和「KM + 风险表」），检索时给你的是带差异说明的候选，而不是一堆撞名条目；
- `verified` 只认实际运行结果，不许虚标。

## 脚本

```bash
python3 scripts/init_library.py    # 初始化图库骨架（幂等；--path 可放别处并自动写配置）
python3 scripts/build_index.py     # 全量重建索引，顺带做一致性校验
```

`build_index.py` 会检查必填字段缺失、id 与目录名不一致、`related` 悬空引用等。跨设备同步之后跑一次即可；手动改过任何 `figure.md` 之后也必须重跑。

## 同步与隐私

整个技能目录（图库内嵌其中）就是一个 git 仓库，`git push` / `git pull` 即为同步；想私有同步，把 remote 换成你自己的私有仓库即可。

你学习所得的条目默认不进公开仓库：`.gitignore` 忽略了 `library/figures/*`（只保留示例条目）以及 `INDEX.json`、`INDEX.md`、`PREFERENCES.md`，这些是你的个人数据。仓库随附的 `figures/000-example-grouped-boxplot` 是一条原创示例，演示完整格式，也是新条目的照抄骨架。日后想公开分享学来的条目，请注意原文献的版权。

## 一些设计上的取舍

- SKILL.md 控制在两百多行：它是每次触发都要读的文件，机制只写到「能指导行为」为止，细节下沉到 `references/`（记录 schema、各来源取图方法、图型词表）；
- 编号不复用：新条目取现有最大编号加一，删除条目连目录一起删并重建索引，其他条目 `related` 里指向它的引用要清掉（脚本会告警）；
- 多候选只列前三：同功能条目往往多条命中，按数据形状匹配 > 意图匹配 > 验证状态排序，每条一句关键差异，不整列甩给你。
